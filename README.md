# מי מביא מה לקמפינג

רשימה משותפת של מי מביא מה. כל מי שיש לו את הקישור יכול לבחור, לסמן ולערוך, בלי שום התחברות.
הדף מתארח ב-GitHub Pages והנתונים נשמרים ב-Firebase Firestore (בתוכנית החינמית).

## הקמה (פעם אחת)

1. **Firebase:** יוצרים פרויקט ב-[Firebase console](https://console.firebase.google.com), ומפעילים בו Firestore Database ב-Production mode.
2. **חוקי גישה:** ב-Firestore Database, בלשונית Rules, מדביקים את התוכן של `firestore.rules` ולוחצים Publish.
   בלי השלב הזה Production mode חוסם הכול, והדף יציג הודעה שאין גישה.
3. **הגדרות:** ב-Project settings, תחת Your apps, מוסיפים Web app ומעתיקים את `firebaseConfig` לקובץ `config.js`.
4. **GitHub Pages:** בהגדרות הריפו, תחת Pages, בוחרים Deploy from a branch, ענף `main`, תיקייה `/ (root)`.
5. פותחים את הדף פעם אחת. הרשימות ההתחלתיות מ-`items.js` נטענות למסד אוטומטית, פעם אחת בלבד.

## הקבצים

| קובץ | מה יש בו |
|---|---|
| `index.html` | המבנה והעיצוב של הדף |
| `app.js` | הלוגיקה והחיבור ל-Firestore |
| `items.js` | הרשימות ההתחלתיות: 54 פריטים משותפים ו-12 פריטים של "כל אחד לעצמו" |
| `config.js` | ההגדרות של פרויקט ה-Firebase |
| `firestore.rules` | חוקי הגישה למסד |
| `og.png` | התמונה שמופיעה בתצוגה המקדימה של הקישור בוואטסאפ |

## טוב לדעת

- כל מי שיש לו את הקישור יכול גם למחוק פריטים, אז הקישור נשאר בקבוצה.
- אפשר לשבץ כמה אנשים על אותו פריט. בהודעות לוואטסאפ פריט משותף מופיע תחת השמות של כל השותפים יחד (למשל "שלומי ורשף"), ופריט של כל הארבעה תחת "כולם".
- ב"כל אחד לעצמו" הרשימה עצמה משותפת (אוסף `personal`), והסימונים ✓ נשמרים רק בטלפון של כל אחד.
- הערכים ב-`config.js` הם מזהים ציבוריים ולא סיסמה. מי שיכול לקרוא ולכתוב נקבע רק ב-`firestore.rules`.
- הדף שומר עותק של הרשימה בטלפון, כך שהיא נפתחת וסימוני ✓ עובדים גם עם קליטה חלשה. השינויים נשלחים כשהחיבור חוזר.
- כדי לטעון מחדש רשימה התחלתית: ב-Firebase console מוחקים את האוסף `items` ואת המסמך `meta/seed` (או את `personal` ואת `meta/seedPersonal`), ופותחים את הדף.
